# 体验目标分类

这些词是帮助表达设计偏好的入口，用来辨认用户在本项目中希望强调的感受与侧重，不是待勾选的基础品质。[默认质量基线](../visual-quality.md) 已覆盖清楚、省脑、可控等适用目标；用户不提也要主动做好，但不据此规定具体机制或开展效率、转化与可用性实验。

当用户表达“高效、专业、安心”等体验期待，却还没说明具体含义时按需读取。以下 14 项是提问与整理的起点，可组合，不是完整问卷或互斥类型。

先用用户熟悉的场景说话，再介绍目标名称。表中的问题和规则只是候选：有上下文答案时直接复用；功能尚不存在时不能凭目标擅自增加。

| ID / 目标 | 可能的用户用语 | 帮助辨认的问法 | 确定后可考察的规则 |
| --- | --- | --- | --- |
| `goal.focus` 专注 | 别分心、突出重点、沉下心做事 | 最希望当前操作过程中不被什么打断？ | 主任务层级、辅助信息显露时机、干扰控制 |
| `goal.efficiency` 高效 | 快、熟练后顺手、少绕路 | 哪个动作会反复做，哪里最不想重复操作？ | 高频操作位置、上下文保留、已有批量与快捷路径 |
| `goal.clarity` 清晰 | 一眼看懂、不乱、找得到 | 最需要立即看懂的是状态、下一步，还是信息之间的关系？ | 命名、分组、层级、状态解释 |
| `goal.low-friction` 省心 | 不费脑、不用设置很多、简单点 | 最想减少的是选择、填写，还是来回查找？ | 默认值、信息复用、按需显示；关键决定仍由用户掌握 |
| `goal.control` 掌控 | 可调整、心里有数、别替我乱改 | 哪些结果希望先预览、可以撤回或手动调整？ | 反馈、预览、修改与恢复路径 |
| `goal.confidence` 安心 | 稳、可靠、敢用 | 最担心误操作、数据不准确，还是不知道有没有成功？ | 后果、来源与时间、执行状态、错误恢复 |
| `goal.approachable` 亲切 | 不冰冷、不吓人、容易接近 | 是语言想更自然，还是操作想更容易理解？ | 具体措辞、熟悉的交互、可见帮助 |
| `goal.professional` 严谨 | 专业、可信、做正事 | 希望通过信息准确、流程可靠，还是视觉秩序感体现？ | 数据与文案精度、一致行为、稳定的排版规则 |
| `goal.exploration` 探索 | 有发现感、愿意逛、能试试 | 用户需要先知道明确目的，还是边看边发现感兴趣的东西？ | 浏览入口、关联线索、可逆试用与返回路径 |
| `goal.expression` 表达 | 有个性、记得住、有品牌感 | 最希望用户记住的是作品、品牌图形、文字语气还是其他特征？ | 表达载体、重点范围、内容与品牌的对应关系 |
| `goal.immersion` 沉浸 | 别打扰、投入进去、内容包围感 | 希望投入的是阅读、欣赏作品，还是持续操作？ | 内容占比、控件显露、避免无关打断 |
| `goal.reading` 耐读 | 看着舒服、长时间不累、愿意读 | 主要是连续阅读，还是快速找某一段信息？ | 阅读宽度、段落节奏、目录与扫描层级 |
| `goal.comparison` 易比较 | 一眼对照、信息在一起、别来回翻 | 做决定时需要把哪些信息同时放在眼前？ | 对齐、统一单位、保留比较上下文 |
| `goal.guidance` 有引导 | 带着我做、别让我迷路、适合新手 | 希望每一步有提示，还是只在遇到困难时获得帮助？ | 步骤组织、上下文帮助、下一步与返回入口 |

## 目标之间如何取舍

先确认目标作用的用户和页面。“新用户需要引导”与“熟练用户需要高效”可能需要不同使用路径；“内容沉浸”与“操作可控”可能通过控件按需显示同时满足。只有同一情境下确实互相影响，才请用户决定优先级。

体验目标不直接指定视觉风格。例如，严谨可以用不同字体和颜色表达；亲切不必使用卡通。外观尚未清楚时，继续读取 [视觉感受维度](visual.md)。

目标清楚后再进入 [候选规则](../principles.md)，根据任务选择规则并补充例外与检查方法。

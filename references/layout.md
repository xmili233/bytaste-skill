# 布局、层级与空间关系

建立布局规则、生成或修改预览及产品界面时读取。以下 LAY-01 至 LAY-08 是 [默认质量基线](visual-quality.md) 在布局中的具体要求，按当前对象适用，无需用户先选择“我希望有视觉层次”。具体构图和参数由内容、平台与偏好决定。

## 先确定当前对象与内容关系

- 规范展示：字体、色彩、参数、规则、组件状态与动态就是内容，通用样本用于说明关系。
- 明确的产品页面：使用已有或用户要求的内容和功能，必要缺口才补问。
- 产品未知：规范可以继续，页面架构保持未知，不发明业务或转向完整产品访谈。

开始排版前，用几句话说明主信息、支撑信息、辅助注释、分组与操作作用域，写入本次相关规范即可。规范总览以样式为主体，参数查看区可以以参数为主体；不让品牌、版本号或装饰默认获得最强强调。

## 默认布局要求

| ID | 必须达到的关系 | 失败线索与适用边界 |
| --- | --- | --- |
| `LAY-01` 主次有依据 | 视觉强调与当前内容的重要性相符；用相对尺度、字重、明暗、位置、留白和分组建立主次 | 装饰或随机图片压过主体、不同职责区块同时争抢注意；标题不必永远最大 |
| `LAY-02` 层级有作用域 | 整页、区域、组件内部的层级衔接；并列信息保留并列关系 | 局部提示无意压过整页、为制造重点破坏比较；同级条目允许等权，区域可各有重点 |
| `LAY-03` 分组与归属清楚 | 标签邻近所属内容，相关对象有共同线索，不同组能辨认 | 标签看起来属于下一组、背景把无关对象误并；间距、容器、标题或边界均可承载分组 |
| `LAY-04` 对齐与比例有秩序 | 需要关联或比较的对象共用合理对齐线，主次区域的空间分配支持内容角色 | 边缘/基线无意漂移、辅助区挤压主内容、固定比例导致裁切；允许光学校正与非对称构图 |
| `LAY-05` 空间有层次和节奏 | 部件、组内、组间与区域间的空间体现关系；重复内容保持一致逻辑 | 所有间距相同导致关系模糊、随机留白或行高；主要依靠间距分组时通常组间更疏，不固定倍数 |
| `LAY-06` 顺序与意义相容 | 顺序影响意义时，视觉重排、线性阅读与操作顺序保留正确关系 | 窄屏拆散说明和对象、键盘顺序与有意义的视觉顺序冲突；可有多种正确顺序，不固定阅读轨迹 |
| `LAY-07` 真实内容与尺寸下成立 | 代表性文字、图像、数量与相关宽度下保留层级及必要内容 | 只对短英文好看、换图后重心跑偏、缩小文字掩盖布局缺陷；必要二维表格/画布可有局部滚动 |
| `LAY-08` 叠层与变化保持结构 | 遮挡关系明确，当前焦点与内容不被意外隐藏；变化过程及结束后连贯稳定 | 浮层错序、固定栏遮住目标、动画后残留空洞/重叠；平面风格仍需正确叠放，动态见 motion.md |

视觉优先级不等于 HTML 标题等级。结构语义按内容表达，不能仅靠放大所有标题，也不能因为一个区域已经有重点就取消其他独立区域的层级。

## 策略和构图按需选择

[布局分类](vocabulary/layouts.md) 提供构图与内容架构选项，不决定默认皮肤。选择时考虑：

- 图底与负空间：哪些形需要被看见，哪些空间连接或分隔内容；留白不默认越多越好。
- 平衡与重心：对称、非对称、视觉重量与位置怎样配合；面积相等不等于视觉重量相等。
- 比例与尺度：文字、图像、区域相对彼此及容器的大小；不强制黄金比例或全屏高度。
- 重复、变化与节奏：哪里保持秩序，哪里因内容分段或表达需要改变跨度与间距。
- 阅读路径：入口、内容顺序和后续落点怎样连接；不把 F 型或 Z 型当所有页面的定律。

先检查内容和容器所需空间，再决定断点与列数。布局技术由项目选择。字体、色彩和图像都会改变上述关系，按 [跨层影响](concepts.md#检查跨层影响) 检查，不只看网格线是否对齐。

## 落地为项目规则

在 design.md 中写明本次内容角色、对齐线、空间分配、分组和适配条件，值引用现有 Token。基线来源与具体实现建议分开；无需把整张基线表抄进每个项目。

```text
规则：LAYOUT-SAMPLE-01
基线来源：ByTaste v0.5.0，LAY-01 / LAY-03 / LAY-07
对象：规范页的排版展示区，不是产品页面
关系：字体实际样本为主，角色名称为次，参数为辅助信息。
实现建议：样本共用左对齐线；宽度不足时参数移到下一行。
取值：使用项目现有文字角色和间距 Token；新取值标为建议。
检查：真实中英文与长参数在相关宽度下主次、归属清楚，无必要内容裁切。
偏好状态：尚未评价具体实现；不伪造用户决定 ID。
```

不同布局可共享 Token 而不共用组件结构。页面覆盖说明规则 ID、范围与真实依据；一次局部反馈不自动改变全部页面。检查步骤与未完成项统一按 [验证约定](verification.md) 处理。

## 依据与边界

[NN/g 视觉层级](https://www.nngroup.com/articles/visual-hierarchy-ux-definition/)、[Atlassian 间距](https://atlassian.design/foundations/spacing/) 和 [Apple 布局](https://developer.apple.com/design/human-interface-guidelines/layout) 提供主次、分组、对齐与适配依据。[IBM 布局](https://www.ibm.com/design/language/layout/tips-and-techniques/) 与 [Every Layout](https://every-layout.dev/layouts/) 提供构图和实现思路，不照搬品牌参数。

Web 的关系语义、顺序和重排分别参考 [1.3.1](https://www.w3.org/WAI/WCAG22/Understanding/info-and-relationships.html)、[1.3.2](https://www.w3.org/WAI/WCAG22/Understanding/meaningful-sequence) 和 [1.4.10](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)。正式标准的适用条件与例外见 [Token 约定](tokens.md#数值与标准边界)，不把这些局部检查当成完整合规结论。
